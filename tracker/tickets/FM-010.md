## Context
No secret is ever committed. Local development reads from a gitignored `.env`;
a committed `.env.example` documents every variable the service needs so a fresh
clone is runnable without guesswork.

## Acceptance criteria
- [ ] `.env` in `.gitignore` in every repo, verified with `git check-ignore .env`
- [ ] `.env.example` committed, listing every variable with a comment and a safe dummy value
- [ ] No password, key or connection string appears in any committed `application*.yml`
- [ ] Profiles: `local` and `prod`, with `local` the default for `bootRun`
- [ ] Service **fails fast at startup** with a clear message if a required variable is missing — not a `NullPointerException` on first use
- [ ] A fresh clone plus `cp .env.example .env` plus compose up produces a working service

## Learning notes
Fail-fast on missing config is worth the effort. The alternative is a service
that boots happily and throws on the first request that touches the missing
value, which is much harder to diagnose. Use `@ConfigurationProperties` with
validation annotations rather than scattered `@Value` strings — you get startup
validation and a typed object instead of stringly-typed config.

The `.env.example` is real documentation. If it drifts from reality, a future you
on a new laptop loses an hour.
