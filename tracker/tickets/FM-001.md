## Context
Polyrepo was chosen in ADR-0001. Six public repos under the
`financemaster-proj` org: `platform`, `api-gateway-backend`,
`auth-service-backend`, `expense-service-backend`,
`investment-service-backend`, `analytics-service-backend`.

Deployable services carry the `-backend` suffix; `platform` does not, because it
holds docs, infra and the tracker rather than a running service.

Clone them all as siblings inside `~/Documents/GitHub/finance-master/` so one
editor window and one agent session can see across the whole system.

## Acceptance criteria
- [x] Six repos exist under the `financemaster-proj` org
- [x] Each has a README stating the service's single responsibility and what it owns
- [x] Each has a Java/Gradle `.gitignore` (no `build/`, `.gradle/`, `.env` committed)
- [x] All six cloned as siblings under the local parent folder
- [x] `platform` contains the existing `docs/` and `tracker/` content, committed

## Learning notes
Write the "what this service owns" line in each README *now*, before any code
exists. A service whose responsibility you cannot state in one sentence has the
wrong boundary, and that is far cheaper to discover today than in sprint 5.
