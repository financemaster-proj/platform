## Context
The rest of the expense resource. Smaller than FM-015 because the conventions
are already set by FM-013 and FM-015 — this ticket applies them and closes the
soft-delete story properly.

## Acceptance criteria
- [ ] `GET /api/v1/expenses/{id}` returns one expense, user-scoped
- [ ] `PATCH /api/v1/expenses/{id}` updates amount, date, description and category
- [ ] `DELETE /api/v1/expenses/{id}` soft-deletes, returns 204
- [ ] `DELETE` on an already-deleted expense returns 404, not 204
- [ ] `GET` on a soft-deleted expense returns 404
- [ ] `PATCH` on a soft-deleted expense returns 404, not a resurrection
- [ ] Another user's id returns 404 on all three verbs, each with a test
- [ ] `updated_at` changes on update and **not** on read
- [ ] Partial update semantics documented: an absent field is unchanged, an explicit `null` is either rejected or clears — decide and test
- [ ] Optimistic locking via `@Version`, returning 409 on a concurrent update
- [ ] An undelete path exists or is explicitly declined, and the decision is recorded

## Learning notes
`DELETE` on an already-deleted record returning 404 rather than 204 is worth
thinking about, because the idempotency argument cuts the other way: DELETE is
supposed to be idempotent, and 204 on a second call is defensible. With soft
delete, 404 is the better answer — the resource is gone from the API's point of
view, and reporting success on a record you cannot see is confusing. Whichever
you pick, pick it deliberately and write the reason down.

Optimistic locking matters more than it looks on a single-user resource. Two
browser tabs, two edits, last-write-wins means the first edit vanishes with no
error anywhere. `@Version` turns that into a 409 the client can handle. It costs
one column.

The explicit-`null` question in PATCH is the one every API gets wrong once.
`{"description": null}` and `{}` are different requests, and JSON deserialisation
usually collapses them to the same object. If clearing a field needs to be
possible, you need to detect presence, not just non-nullness.
