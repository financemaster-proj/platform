## Context
Integration tests run against real Postgres in a container, never H2. H2 has a
different dialect, different transaction semantics and no Postgres-specific
types — a test that passes on H2 and fails on Postgres is worse than no test.

A start exists: `TestcontainersConfiguration` declares a `PostgreSQLContainer`
with `@ServiceConnection`, and `ExpenseServiceApplicationTests.contextLoads()`
is green. What is missing is a shared base class, container reuse, and any test
that asserts behaviour.

## Acceptance criteria
- [ ] An abstract base test class starting Postgres **once**, reused across all integration test classes
- [ ] Container reuse enabled, so the suite does not pay startup per class
- [ ] Flyway migrations run against the container before tests
- [ ] One green test: insert a category via the repository, read it back, assert every field
- [ ] One green test asserting `(user_id, name)` uniqueness is enforced **by the database**, not by application code
- [ ] One green test asserting two different `user_id`s *can* both have "Groceries"
- [ ] One green test asserting a soft-deleted name can be reused (the partial index from FM-005)
- [ ] `./gradlew integrationTest` passes from clean
- [ ] `./gradlew test` starts **no** container and completes in under 5 seconds
- [ ] Verified with `docker ps` that `./gradlew build` starts nothing

## Learning notes
The singleton-container pattern matters. A naive `@Testcontainers` on each class
starts a fresh Postgres per class, and a 40-test suite takes ten minutes. Start
one, share it, and roll back or truncate between tests.

Test the unique constraint **through the database**. A `findByName` guard before
insert is a race condition: two concurrent requests both see nothing and both
insert. The database constraint is the only real one, and your code has to
handle the exception it throws.

The third and fourth tests are the ones people skip, and they are the ones that
prove the constraint is scoped correctly. The first two pass just as happily
against a wrong `UNIQUE (name)`.
