## Context
First service skeleton. No business logic — the goal is a service that starts,
proves it can reach its dependencies, and documents itself.

Package layout follows ADR-0006: package by feature, not by layer.

## Acceptance criteria
- [x] Starts on 8082 via `./gradlew bootRun`
- [ ] `GET /actuator/health` returns 200 with a Postgres component status
- [x] Health endpoint reports DOWN when Postgres is stopped — verified by stopping it
- [x] `GET /actuator/health/readiness` and `/liveness` both exposed
- [ ] Swagger UI served, OpenAPI JSON at `/v3/api-docs`
- [x] Only `health` and `info` exposed over HTTP; no `env`, `beans` or `heapdump`
- [ ] Graceful shutdown enabled with a 30s timeout

## Verified 2026-11-20

With Postgres stopped the endpoint returns **HTTP 503** and `{"status":"DOWN"}`
in ~4ms, on both the first and second call. Two things worth noting that the
criterion did not explicitly ask for:

- It returns 503, not 200-with-a-DOWN-body. Load balancers and Kubernetes read
  the status code, not the JSON, so a 200 here would keep traffic flowing to a
  broken instance.
- It fails in milliseconds rather than blocking on Hikari's 30s connection
  timeout. A health check that blocks is a classic incident: readiness probes
  time out, instances get restarted, and the blocked threads exhaust the
  request pool under load.

The service also recovered on its own when Postgres came back - no restart
needed, Hikari discarded the dead connections and opened new ones.

Still open: health details are hidden, so `UP` does not show *which* components
were checked; and springdoc is not wired.

## Learning notes
Readiness and liveness are not the same thing and conflating them causes real
outages. Liveness answers "is this process wedged, restart it"; readiness
answers "can this instance serve traffic right now". A service waiting on a
database is *not ready* but is perfectly *alive* — if your liveness probe checks
the database, a brief database blip restarts every instance you have.

Exposing `/actuator/env` publicly leaks your entire configuration including
secrets. Default-deny the actuator surface.

springdoc-openapi is **not** available in Spring Initializr — you add it to
`build.gradle.kts` by hand. Worth noticing: Initializr covers Spring-managed
starters, not the wider ecosystem.
