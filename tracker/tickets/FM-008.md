## Context
In a four-service system, "which log lines belong to this one request" is
unanswerable without a correlation ID threaded through everything. Establish the
pattern here, in the first service, so the other four copy something that
already works. Retrofitting it across five services in sprint 7 is miserable.

This lands before FM-009 because the Problem Details 500 response has to carry
the correlation ID, which has to exist first.

## Acceptance criteria
- [ ] Logs are single-line JSON in the `prod` profile, human-readable in `local`
- [ ] Every line carries `timestamp`, `level`, `logger`, `message`, `service`, `correlationId`
- [ ] A servlet filter reads `X-Correlation-Id` from the request, or generates a UUIDv7 if absent
- [ ] The correlation ID is in MDC and appears on every log line for that request
- [ ] The correlation ID is echoed back on the response in `X-Correlation-Id`
- [ ] MDC is cleared in a `finally` block
- [ ] Verified: two sequential requests on the same pooled thread log different correlation IDs
- [ ] No secrets, tokens, passwords or full request bodies are ever logged — grep the codebase to confirm
- [ ] Field names documented in `platform/docs/runbooks/logging.md` as the project-wide convention

## Learning notes
Clearing MDC in `finally` is not optional. Servlet threads are pooled and
reused; leak a correlation ID and the next unrelated request logs under the
previous request's identity. That is the kind of bug that makes an incident
unreadable — you follow one id and find two users' requests under it.

The verification step is what proves you got it right. A single request looks
correct whether or not you cleared MDC.

Decide the field names now and write them down. `userId` in one service and
`user_id` in another means two queries where there should be one, and you will
not notice until sprint 7 when you have five services' logs to join.

Accepting an inbound `X-Correlation-Id` is what lets the gateway set it once and
have it flow through every service. Generating one when absent is what makes
direct `curl` testing still traceable.
