## Context
One compose file in `platform/infra/` boots everything the system depends on.
Your own services run on the host via `./gradlew bootRun` — containerising them
for local dev destroys the iteration loop. They get containerised in sprint 9
for deployment.

Postgres runs as a single container with four separate logical databases, which
keeps "database per service" structurally true while costing one container.

## Acceptance criteria
- [x] Postgres 17 with an init script creating `fm_auth`, `fm_expense`, `fm_investment`, `fm_analytics`, each with its own role and password
- [x] No role has access to another service's database — verified by connecting as `fm_auth` and failing to read `fm_expense`
- [x] Redis 7 on 6379
- [x] Kafka in KRaft mode on 9092 — no Zookeeper
- [x] kafka-ui on 8090, able to list topics
- [x] Prometheus and Grafana present but behind a compose profile, not started by default
- [x] Named volumes so data survives `down`; a documented command for wiping it deliberately
- [x] Healthchecks on Postgres and Kafka so dependent startup is predictable
- [x] `platform/docs/runbooks/local-setup.md` written: start, stop, wipe, troubleshoot

## Known conflict on this machine

A **native PostgreSQL service is running and holding 127.0.0.1:5432**
(`systemctl is-active postgresql` → active). `docker compose up` will fail with
`address already in use` unless this is handled.

Options, in order of preference:

1. **Map the container to a different host port**, e.g. `15432:5432`, and put
   the port in `.env` as `DB_PORT`. Survives reboots, touches nothing else on
   the machine, and config-driven ports are the right habit anyway (FM-010).
2. `sudo systemctl stop postgresql && sudo systemctl disable postgresql` — only
   if nothing else on this machine depends on it.
3. Stopping the native service by hand each session. Don't; you will forget.

The other project's containers (`postgres-assembly` on 25432, `broker_assembly`
on 9093, `zookeeper_assembly` on 2181) do **not** conflict. 6379, 9092, 8080 and
8082 were all free when checked.

## Learning notes
The per-database role isolation is the point of this ticket. If every service
connects as `postgres` superuser, "database per service" is a comment in a
README rather than a property of the system. Prove the isolation with a failed
query and paste the error into the runbook.

Compose profiles keep startup fast — you do not want to wait for Grafana every
time you want a database.
